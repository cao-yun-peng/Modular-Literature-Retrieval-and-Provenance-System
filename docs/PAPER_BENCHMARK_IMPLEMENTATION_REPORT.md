# 论文测评体系实施记录

实施日期：2026-09-09。软件与入库已验证；人工标签与正式质量结论尚未验证。

## 已落地

- 在原 `scripts/evaluate.py` 中增加新版测评入口，保留旧 JSON 格式和旧调用路径。
- 新增 `scripts/benchmark.py`：语料盘点、独立入库、DeepSeek 出题、人工复核、冻结、证据映射、三路候选池、检索/服务运行、离线重算、配对比较及回归检查。
- 金标使用论文哈希、PDF 物理页码和原文字符位置；证据组支持跨块、替代段落和跨论文联合覆盖。
- 实际调用项目的 `QueryKnowledgeHubTool`，保存 Evidence Bundle、请求、候选、trace、降级和错误。另有 MCP stdio 协议测试。
- 比较固定 RRF Top-20 的重排贡献，以及同一原始命中的邻块/父块扩展；单列 12,000 字符预算成绩。
- 限制测试集评分：完整人工审核、24 次盲复核、20 题开发试点保留、冻结版本、开发集选型后才可进入测试集。

## 验证与已知限制

139 项相关测试通过，覆盖原测评入口、评分口径、异常分母、索引绑定、人工冻结、真实服务适配、MCP 序列化、重排降级、人工映射、离线标签迁移和 BM25 索引读写。日志位于 `data/paper_benchmark/verification_final.log`。测试不替代人工科学内容核验。

实际入库发现原 BM25 构建存在重复扫描瓶颈，已保持统计量、词序、文档顺序和排名不变地改为一次遍历；等价性及已有索引测试均通过。

测评索引使用论文解析器、层级切分和规则转换，关闭 LLM 改写，保留现有 nomic-embed-text。GROBID 不可用，实际使用解析降级路径；这会影响页码等定位能力。11,124 个检索块中，302 个带 page_start 字段，10,822 个为空。空页码是合法返回，但会降低定位完整率。不要将独立测评配置等同于生产默认配置。

批量入库使用相同 Ollama 模型；检索块最长 350 字符，未触发原 1,000 字符截断阈值。单条与批量接口的探针 cosine 相似度为 0.9999999999999993。向量、BM25 和父子块关系分别记录哈希。

当前性能报告区分首个请求与后续预热请求，不宣称控制了模型服务器或操作系统的冷缓存。手工 PDF 不含已核验 Zotero 附件身份，真实全文交接标为未覆盖。

操作说明见 `docs/PAPER_BENCHMARK_MANUAL.md`；人工入口为 `data/paper_benchmark/v1/review_120.html` 和 `pilot_v2/review.html`。完成真实人工审核后才能冻结并发布正式基线。

## 首轮实际运行

60 道开发集草稿完成了 360 次三路检索请求；20 道试点完成了 40 次完整服务请求，以及三轮、共 720 条固定候选池的重排/扩展消融记录。查询运行全部成功，所有报告仍为 provisional。服务试跑只有一轮，不等同于三轮正式服务基线。

开发集 Hybrid 的文献 Hit@10 为 87.04%，严格 Evidence Recall@10 为 8.33%。自动匹配提示明显的原文/解析/分块差异，不能将其直接解释为人工核验后的准确率。MRR/nDCG 因缺少相关性标注保持 N/A。

已导出 1,726 条开发集候选与原文映射建议；人工审核后的映射可以进入预算约束下的评分。360 条检索记录已离线重算，所有共有指标与原运行一致。完整报告见 `data/paper_benchmark/v1/BASELINE_DIAGNOSTIC_REPORT.md`，六份对照报告位于同级 comparisons/。未查询测试集，未伪造审核记录或预先选择最终方案。
